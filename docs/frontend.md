# Фронтенд: страница и компоненты

React 19 + Next 16 App Router. Стили — `app/globals.css` (см. `docs/design.md`).
Серверные компоненты по умолчанию; `"use client"` только там, где есть состояние.

## Структура лендинга (`app/page.tsx`)

```
SiteHeader                      клиентский: сессия, коннект, бургер
main
  Hero            #top          заголовок, слоган, CTA (PLAY / BUY $VLTR — заглушка), соцсети
  HowItWorks      #how          4 шага + SkinShowcase + полоса тиров
  GameSection     #game/#board  Vault + Leaderboard (клиентская обёртка с общим состоянием)
  TokenSection    #token        лестница буста за холд, пул из фисов, fair launch, флайвил, «что мы НЕ делаем»
  Roadmap         #roadmap      LIVE NOW / NEXT UP, дележ фисов, кривая выплат, «чего не будет никогда»
  TrustSection    #trust        3 карточки доверия + «честный статус» (live/soon/not yet)
  Faq             #faq          9 вопросов в <details>
SiteFooter                      бренд, соцсети, дисклеймеры
```

`export const dynamic = "force-dynamic"` на странице — обязательно: статический HTML не
может получить per-request CSP-nonce (см. `docs/security.md`).

## Клиентские и серверные компоненты

| Компонент | Тип | Роль |
|---|---|---|
| `Hero`, `HowItWorks`, `TokenSection`, `TrustSection`, `Faq`, `SiteFooter`, `Socials` | server | статический контент и копирайтинг |
| `SiteHeader` | client | `useSession()`, `ConnectButton`, бургер (Esc + блок скролла) |
| `GameSection` | client | общий стейт игры и борда |
| `Vault` | client | игровой экран |
| `Leaderboard` | client | борд, поллинг, отдаёт ранг наверх |
| `ConnectButton` | client | wagmi, SIWE, модалка выбора кошелька, смена сети |
| `ProfileEditor` | client | ник + переключатель приватности адреса |
| `TelegramLink` | client | привязка/отписка бота напоминаний — работает и без кошелька |
| `SkinShowcase` | client | витрина скинов (нужен размер комьюнити) |
| `SafeSprite` | server | чистая отрисовка спрайта по уровню |

`Providers` (`app/providers.tsx`) — `WagmiProvider` + `QueryClientProvider`,
`QueryClient` создаётся через `useState`, чтобы не пересоздавался на ререндерах.

## Поток состояния

```
GameSection  ─ rank, players ─►  Vault ──► SafeSprite (скин)
     ▲                            │
     └── onRank ── Leaderboard ◄── onStackChanged (кранк → перечитать борд)
```

Ранг считает сервер (`/api/leaderboard`) — `GameSection` держит его и отдаёт в игру,
чтобы не пересчитывать скин на каждом опросе состояния.

## Vault.tsx — игровой экран

Поллинг `/api/state` раз в **2.5 с**, плюс немедленный refetch на `visibilitychange`
(вернулся на вкладку — увидел актуальное). Кранк — `POST /api/crank`, ответ применяется
тем же `applyResponse`, что и опрос.

**Плавность между поллами.** Локальный таймер (250 мс; 1 с при reduced-motion)
экстраполирует стек: `stack + ratePerSec × min(elapsed, доКонцаОкна)`. Это чистая
косметика — на следующем ответе сервера значение затирается серверным. Экстраполяция
ограничена концом окна завода, чтобы цифра не убегала за реальное начисление.

Что рисуется:
- **tierbar** — текущий тир и следующий порог;
- **машина**: спрайт сейфа + камера с монетами (`coinCount` — от прогресса внутри тира,
  капы `COIN_CAP`), падающие монеты `.drop` не чаще одной в 520 мс;
- **ридауты** STACK / STREAK / ×MULT и SVG-шкала множителя (нормировка до ×15);
- **метки за стрик** (`.streakbadges`, `lib/skins.ts` → `STREAK_BADGES`) — вторая,
  независимая от ранга ось косметики, см. `docs/design.md`;
- **статус фазы** (`role="status"`) — короткая метка-пилюля (`OFF` / `WINDING` /
  `WINDOW OPEN` / `RAIDED`) плюс детали рядом (сколько осталось до окна/рейдера —
  из `phaseEndsInMs`, ничего не пересчитывается на клиенте) и отдельная строка
  `.loss-note`, что конкретно теряется: в `ready` — прогноз (`view.raidPreview`,
  считает сервер из текущего стека и `GAME.SKIM`), в `stall` — фактическая сумма из
  последнего события `raid` (держим в стейте, потому что сервер отдаёт `raid` только
  один раз — в ответе, где рейд применился, а не на каждом опросе);
- кнопка кранка с меняющимся лейблом: `CRANK` / `WINDING…` (disabled) / `RESTART` (danger);
- **вспышка рейда** — только если `raid.lost > 0` и не включён reduced-motion;
- **боковая панель**: HOLDER BOOST (или CONNECT), `ProfileEditor` при подключённом
  кошельке, `TelegramLink` (видна ВСЕГДА — анонимные сессии тоже привязывают бота, это
  30 игроков из 34), THE RULES.

## TelegramLink.tsx — привязка бота напоминаний

Опрашивает `GET /api/telegram/link` при монтировании и на возврате вкладки
(`visibilitychange` — игрок мог привязать бота, переключившись в Telegram). Если владелец
ещё не завёл бота (`configured: false`), компонент не рисует вообще ничего — ни заглушки,
ни "скоро": обещание даты на кнопке напоминаний было бы нарушением гардрейла копирайтинга.

Три состояния: не привязан (кнопка "GET REMINDERS ON TELEGRAM" → `POST /api/telegram/link`
выдаёт код) → код выдан (deep link `t.me/<bot>?start=<код>` собирается из ОДНОЙ константы
`TELEGRAM_BOT_USERNAME`, lib/links.ts, — той же, что и ссылка «REMINDER BOT» в шапке/футере)
→ привязан (кнопка UNLINK). `chatId` в этом компоненте не появляется никогда — сервер его
и не отдаёт.

Карточка HOLDER BOOST рисует **всю лестницу тиров** с подсветкой своей ступени и строку
«+N $VLTR → следующая ступень». Сама лестница статична и приходит пропсом из серверного
`app/page.tsx` (`holderLadder()`), а не в каждом ответе поллинга; «сколько докупить»
считает сервер в `/api/boost/refresh`, потому что для этого нужно чтение чейна.

Стек в ридауте показывается с дробными разрядами, пока он мал: на прод-ставке
(0.012 $STACK/с) целая часть не менялась бы 83 секунды, и игра выглядела бы сломанной.
Текст пустой камеры зависит от **фазы**, а не от стека, — иначе во время завода там
висело бы «machine is off».

## Роадмап на странице

Секция `#roadmap` (`app/components/Roadmap.tsx`) повторяет [roadmap.md](roadmap.md) словами
для игрока. Два правила:

- **никаких дат** на том, что не в нашей власти: просроченная дата — это долг, за которым
  приходят в комментарии, и репутационно она дороже самой фичи;
- **кривая выплат публикуется вместе с формулой** и считается из `lib/payout.ts`, а не
  вписана процентами в разметку. Игрок должен уметь пересчитать долю сам (`(11 − N) / 55`),
  а страница — не иметь физической возможности разойтись с документом и с тем, что реально
  выплачено.

Раскладка у секции своя (`.rm-*`), а не переиспользованная сетка статусов из
`TrustSection`: та рассчитана на полноширинную карточку и в узких колонках сжимала
описание в полосу шириной в пару слов. Здесь заголовок пункта идёт отдельной строкой,
описание — под ним во всю ширину карточки, а роль ярлыка выполняет цветная полоса слева
(неон — сделано, золото — в планах, ржавчина — не будет никогда).

## Обработка сетевых ошибок

Принцип: **последнее состояние остаётся на экране**, сверху — честный баннер.
Белого экрана и обнуления цифр быть не должно — игрок решит, что стек потерян.

- `Vault`: `.netbanner` «Can't reach the machine. Your stack is safe on the server» + RETRY;
- `Leaderboard`: `.lb-err` «showing the last snapshot», старые строки остаются;
  до первой загрузки — skeleton-строки;
- `SkinShowcase`: пока размер комьюнити неизвестен (`players === null`) не показывает
  ни замки, ни открытые скины — иначе мигнёт неверным состоянием;
- границы ошибок: `app/error.tsx` (секции), `app/global-error.tsx` (падение layout,
  собственная разметка без зависимостей темы), `app/not-found.tsx`.

## ConnectButton — три состояния

1. **не подключён** → `CONNECT` → модалка со списком коннекторов (дубликаты EIP-6963
   отфильтрованы по имени);
2. **подключён, не подписан** → `SIGN IN` (SIWE-флоу) + «✕» для disconnect;
3. **подключён и подписан** → короткий адрес → модалка с полным адресом,
   «ADD / SWITCH TO ROBINHOOD CHAIN» и DISCONNECT. При неверной сети — кнопка `WRONG NET`.

### Chain ID в SIWE-сообщении

Берётся из `useAccount().chainId` — это сеть **кошелька**. Не из `useChainId()`: тот
отдаёт сеть из нашего wagmi-конфига, а в нём один чейн, поэтому в сообщение всегда
уходил `robinhoodChain.id`, где бы кошелёк ни стоял.

Кошельки (в частности Phantom) разбирают EIP-4361 и сверяют `Chain ID` с активной сетью:
при несовпадении просто отказываются подписывать — вход выглядел сломанным наглухо.

Сервер сеть **не пинит** намеренно: для входа она не нужна (подпись сообщения не требует
RPC), а гонять человека переключать сеть до логина — лишний барьер. Проверено: вход
проходит с 88991, 1, 8453, 137.

### Сеть кошелька игре безразлична

Раньше при несовпадении показывалась красная кнопка `WRONG NET`. Это было неверно
дважды: она сообщала о поломке, которой нет, и вела в тупик — переключение на
chainId-плейсхолдер невозможно, а `switchChain` (как и `connect`) ошибку глотал молча.

Игре сеть кошелька не нужна вообще: вход — это подпись (RPC не требует), баланс $VLTR
читает сервер на своём RPC, транзакций сайт не отправляет. Сеть нужна только чтобы
купить или держать токен.

Поэтому теперь:

- нет `NEXT_PUBLIC_RH_RPC_URL` → подсказки нет совсем (предлагать нечего);
- сеть настроена и не совпала → нейтральная `+ ROBINHOOD CHAIN`, не ошибка;
- переключение через `switchChainAsync`, неудача объясняется текстом;
- в модалке кошелька прямо сказано, что сеть на игру не влияет.

### Ошибки кошелька

Разбираются по `name`/`code` со сверкой по всей цепочке `cause` (`errorMatches`), а не
по тексту сообщения: текст локализуется кошельком и меняется между версиями библиотек.

- `UserRejectedRequestError` / код `4001` → **ошибкой не считается**, это просто отмена,
  сообщение не показывается;
- `ProviderNotFoundError` → «кошелёк не найден» с подсказкой поставить расширение или
  открыть страницу во встроенном браузере кошелька. Для generic-инжекта формулировка
  другая: «Browser Wallet» — не продукт, предлагать его «установить» бессмысленно;
- остальное → «Couldn't connect — try again.».

У **входа** два принципиально разных места отказа, и их нельзя смешивать: кошелёк не
отдал подпись (`SignStepError`) и сервер её не принял (`VerifyRejected` с кодом причины).
Раньше оба показывались как «Sign-in failed», из-за чего поломка была неотлаживаемой —
по экрану невозможно понять, чинить кошелёк или бэкенд. Теперь коды сервера
(`message_rejected`, `bad_signature`, `nonce_missing`, …) переводятся в конкретные
подсказки, а ошибка кошелька показывается вместе со своим `name`.

**Коннект только через `connectAsync`.** Обычный `connect` из `useConnect()` —
fire-and-forget: он не реджектит промис, ошибка уходит в состояние хука. С ним `await`
проходил всегда, модалка закрывалась даже при неудаче, а `catch` был мёртвым кодом —
пользователь видел молча закрывшуюся модалку и решал, что сломан сайт. Модалка теперь
закрывается **только по факту успеха**.

## Leaderboard.tsx

Поллинг раз в **8 с** + на `visibilitychange` + при изменении `refreshKey` от родителя
(после кранка стек изменился). Показывает общий сейф, число стакеров, отсчёт до конца
недели, зону выплат («ranks 1–10 are in the money»), подсветку `you` и отдельную строку
«you — N off the top 10», если игрок вне топа.

Приватность на клиенте: если `label` уже равен короткому адресу — не дублируем его,
показываем только кликабельную ссылку в explorer (`NEXT_PUBLIC_RH_EXPLORER`).
Без explorer в env адрес отображается текстом, без ссылки. Боты помечены тегом `test`.

## Копирайтинг: гардрейлы

Тексты — часть безопасности продукта, менять осторожно:
- **никакой токеномики по бакетам** (fair launch: нет тим-аллокации, пресейла, казны);
- **не держим средства пользователей** — нигде не намекать на депозиты/стейкинг-контракт;
- **никогда не называть цифру APY/доходности**; `$STACK` — игровой счёт без ценности;
- пул — **приз за место в игре**, а не дивиденд на холд (юридически важно,
  см. `docs/leaderboard-rewards.md`);
- секции «WHAT WE DO NOT DO» и «HONEST STATUS» проговаривают ограничения прямо.
  Если что-то из написанного перестало быть правдой — это баг, а не мелочь.
