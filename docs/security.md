# Безопасность

Что защищаем: **призовой пул из реальных токенов** (борд решает, кому платить) и
**кошельки игроков** (сайт в вебе про крипту — цель для дрейнеров).
Чего не защищаем: пользовательских средств у нас нет — кастодии нет by design.

## CSP с nonce

`proxy.ts` выдаёт на каждый запрос свой nonce и ставит заголовок:

```
script-src 'self' 'nonce-<random>' 'strict-dynamic'    (прод)
script-src 'self' 'unsafe-inline' 'unsafe-eval'        (dev — Turbopack HMR требует)
default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:
connect-src 'self' https: wss:; object-src 'none'; base-uri 'self';
form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests (прод)
```

Зачем именно это: главный способ украсть крипту с сайта — подсунуть в страницу чужой
скрипт, который перехватит взаимодействие с кошельком. Со `strict-dynamic` и nonce
инъектированный `<script>` просто не выполнится, даже если XSS где-то есть.

Компромиссы, сделанные осознанно:
- `style-src 'unsafe-inline'` — Next инлайнит стили; инъекция стилей не даёт дрейна;
- `connect-src https: wss:` — кошелёк и RPC ходят на произвольные хосты, а скрипт всё
  равно не выполнится без nonce;
- лендинг переведён в `force-dynamic`: статический HTML собирается один раз и
  per-request nonce получить не может.

Базовые заголовки (`nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`,
`Permissions-Policy`, HSTS) — в `next.config.ts`.

Проверено на прод-сборке: сайт гидрируется, нарушений CSP нет.

## Аудит секретов перед пушем

```bash
npm run check:secrets
git config core.hooksPath .githooks   # один раз после клона — хук pre-push
```

Четыре проверки:
1. **запретные файлы во всей истории**: `.env*` (кроме `.env.example`), `.data/`,
   `node_modules/`, сгенерированный Prisma-клиент, `*.pem`, `*.key`, `id_rsa`, `credentials*`;
2. **паттерны секретов в содержимом всех коммитов**: приватные ключи, GitHub/OpenAI/AWS/Slack
   токены, строки подключения с паролем, **приватный ключ EVM** (`0x` + 64 hex),
   WalletConnect projectId (строки с `placeholder|example|dev-insecure` игнорируются);
3. **рабочее дерево**: неотслеживаемые и не заигнорированные чувствительные файлы;
4. **покрытие `.gitignore`** для `.env.local`, `.data/players.json`, `node_modules`,
   `lib/generated/prisma`.

Смотрится **вся история**, а не только текущее состояние: при пуше уезжают все коммиты,
и секрет, удалённый следующим коммитом, всё равно остаётся в git навсегда.

Правила:
- никаких реальных значений в `.env.example` — только пустые плейсхолдеры;
- секреты живут в `.env.local` (локально) и в env-переменных Vercel (прод);
- обход `git push --no-verify` — только с явной причиной.

## Границы проекта: чего мы намеренно не делаем

- **не держим средства пользователей** — нет депозитов, кастодии и vault-контракта.
  Настоящая кастодия требует серьёзного аудита, которого нет;
- **не шлём транзакций и не просим approve** — только чтение публичного баланса и
  проверка подписи сообщения;
- **не автоматизируем выплаты пула** — деньги реальные, выплаты делает команда вручную
  (см. `docs/leaderboard-rewards.md`);
- **не обещаем APY/доходность** цифрой; `$STACK` — игровой счёт без денежной ценности;
- **не пишем «audited»** — контракта, держащего средства, нет, и аудита нет.
  Секция «WHAT WE DO NOT DO» на сайте проговаривает это явно.

## Открытое к закрытию перед реальным запуском

1. **Подключить Vercel KV / Upstash** и выставить `KV_REST_API_URL` + `KV_REST_API_TOKEN`.
   Код лимитера уже умеет общий стор, но без этих env откатывается в память процесса,
   а она на serverless не шарится между инстансами → лимиты обходятся размазыванием
   запросов. Проверка: `/api/health` должен отвечать `rateLimit: "shared"`.
2. **Убрать тестовых ботов**: `node scripts/seed-bots.mjs --clear`.
3. **ERC-1271** для смарт-контрактных кошельков (нужен рабочий RPC).
4. **Анти-мультиаккаунт**: политика при смене кошелька, привязка device/IP.
5. **Ротация `CrankLog`**: журнал пишется бессрочно. На объёме понадобится удаление
   старше N месяцев — иначе таблица растёт линейно по числу кранков.
