# Web3-слой: сеть, токен, кошелёк, буст

`lib/chain.ts` · `lib/vltr.ts` · `lib/wagmi.ts` · `app/components/ConnectButton.tsx`

## Что вообще делает блокчейн в этом проекте

Ровно две вещи:
1. **проверка владения кошельком** — подпись сообщения (SIWE), без транзакции и без газа;
2. **чтение публичного баланса $VLTR** — чтобы включить буст ×5.

Больше ничего. Нет своих контрактов, нет транзакций от имени пользователя, нет
`approve`, нет кастодии. Это осознанное сужение поверхности атаки: через такой флоу
задрейнить нечего, а полноценный vault-контракт требовал бы аудита, которого нет.

## Сеть: Robinhood Chain (Arbitrum Orbit L2)

`lib/chain.ts` собирает `viem`-чейн из env — **все значения плейсхолдеры**, реальные
подставляются в проде:

| env | Дефолт | Смысл |
|---|---|---|
| `NEXT_PUBLIC_RH_CHAIN_ID` | `88991` (PLACEHOLDER) | chainId сети |
| `NEXT_PUBLIC_RH_RPC_URL` | пусто | пусто → чтение баланса выключено |
| `NEXT_PUBLIC_RH_NAME` | `Robinhood Chain` | подпись в кнопке смены сети |
| `NEXT_PUBLIC_RH_EXPLORER` | пусто | ссылки на адреса в борде |

Флаги: `RPC_CONFIGURED` (есть RPC), `VLTR_CONFIGURED` (есть RPC **и** адрес токена).
Пока сеть не настроена, всё, кроме буста, работает: подпись сообщения RPC не требует.

## Токен $VLTR

| env | Дефолт | Смысл |
|---|---|---|
| `NEXT_PUBLIC_VLTR_ADDRESS` | пусто | адрес ERC-20 |
| `NEXT_PUBLIC_VLTR_DECIMALS` | `18` | десятичные |
| `NEXT_PUBLIC_VLTR_BOOST_MIN` | `1` | минимум на балансе для буста |

Токен **ещё не запущен**. Запуск планируется fair-launch через лаунчпад: без пресейла,
тим-аллокации и казны, ликвидность лочится автоматически.

## Буст ×5: почему его ставит только сервер

```ts
computeBoost(address) → readVltrBalance(address) >= VLTR.boostMin
```

`lib/vltr.ts` создаёт `publicClient` на серверном RPC и читает `balanceOf` через
`erc20Abi`. Ошибка/отсутствие конфига → `0` → буста нет (fail-closed).

**Критично:** клиент буст не задаёт и не может. Если бы флаг приходил из браузера,
любой не-холдер объявил бы себя холдером и получил ×5 в борде, который делит реальные
токены. Буст пишется в стейт игрока в двух местах, и оба серверные:
`POST /api/auth/verify` (при входе) и `POST /api/boost/refresh` (перечитать баланс).

`DEV_FORCE_BOOST=1` включает буст принудительно — только для локального теста пути буста,
пока нет реальной сети. **В проде не выставлять.**

Экономический смысл ×5 (а не ×1.5) — в `docs/leaderboard-rewards.md`.

## Подключение кошелька

`lib/wagmi.ts`: `createConfig` с одним чейном, коннекторы —
`injected({ target: "metaMask" })`, `injected({ target: "phantom" })` и общий `injected()`.
Последний плюс автоподхват **EIP-6963** дают Rabby, OKX, Brave и остальные установленные
кошельки автоматически. `ssr: true`.

Своя кнопка и модалка вместо connectkit: connectkit несовместим с React 19, к тому же
нужна своя пиксельная тема. WalletConnect/Coinbase SDK не тянем — лишние зависимости;
включим, когда появится `NEXT_PUBLIC_WC_PROJECT_ID` (нужен для внешних мобильных кошельков).

Смена сети — `useSwitchChain` (кнопка «ADD / SWITCH TO ROBINHOOD CHAIN» и предупреждение
`WRONG NET`, когда `chainId !== robinhoodChain.id`).

Флоу входа и его проверки — `docs/auth-session.md`.

## Что нужно от Егора для полного включения web3

1. реальные `chainId` / RPC URL / explorer Robinhood Chain;
2. адрес контракта $VLTR после запуска + решение по `BOOST_MIN`
   (сколько токенов считается «холдом»);
3. опционально `NEXT_PUBLIC_WC_PROJECT_ID` для WalletConnect.

До этого сайт полностью играбелен, просто буст не активируется.

## Бэклог web3

- **ERC-1271** — вход смарт-контрактными кошельками (Safe и подобные); требует рабочего RPC;
- кэширование баланса, чтобы `boost/refresh` не бил в RPC на каждый клик;
- индикация «сколько ещё токенов до буста» в UI (сейчас бинарно: есть/нет).
