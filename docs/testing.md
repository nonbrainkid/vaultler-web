# Тесты и dev-инструменты

## Команды

```bash
npm test              # vitest run — юнит-тесты чистой логики
npm run test:watch    # то же в watch
npm run test:auth     # e2e SIWE против запущенного dev-сервера
npm run test:boost    # e2e холдерского буста против локального чейна (см. ниже)
npm run check:secrets  # аудит секретов (рабочее дерево + вся история git)
```

## Юнит-тесты (vitest)

Покрыты **чистые модули** — те, что не читают время из окружения и не трогают БД.
Это осознанно: вся логика, которую может попытаться обмануть игрок, живёт именно там.
Исключение — `ratelimit`: там подменяется модуль `kv`, чтобы проверить поведение при
недоступном Redis, не выходя в сеть.

| Файл | Что проверяет |
|---|---|
| `lib/game.test.ts` | множитель и стрик, **лестница холдерского буста** (монотонность ступеней, граница тира по доле, потолок ×5 для кита, вогнутость кривой, невыгодность дробления бэга, мусорный тир → «буста нет»), пороги тиров стека, все четыре фазы, отказ кранка во время `winding`, рост стрика в окне `ready`, свежий стрик после `stall`, начисление строго внутри окна завода, **идемпотентность `settle`**, рейд (ским + сброс стрика), **защита от накрутки времени**, `phaseAt` для журнала кранков, `hydrateState` (легаси-формат и fail closed) |
| `lib/store-file.test.ts` | **свежесть файлового стора**: чужая запись видна следующему чтению (регрессия «стакание обрывается через 2.5 с»), внешняя правка файла сидером, запись одного экземпляра не затирает другой, удалённый файл = сброс, битый JSON не обнуляет игрока, легаси `boost:true` → первая ступень, уникальность ника против свежего файла, параллельные кранки не начисляют дважды |
| `lib/vltr.test.ts` | анти-дуст-порог в `bigint` (граница, decimals, огромные балансы), **доля в эмиссии в ppb** (точность на балансе кита, перевод порога ступени в токены и обратно, самокалибровка при росте эмиссии) |
| `lib/ratelimit.test.ts` | ключ и TTL фиксированного окна, граница лимита, обнуление на новом окне, `SET NX` для кранка, **откат в память при недоступном Redis** (запрос не падает), независимость ключей, `rateLimitBackend`, разбор `X-Forwarded-For` |
| `lib/leaderboard.test.ts` | недельный отсчёт, сортировка по стеку, сумма общего сейфа, приватность ярлыков (ник / короткий адрес / anon / **скрытый адрес не отдаётся**), отметка «you» и ранг, живой стек |
| `lib/skins.test.ts` | гейтинг «TOP N открыт только при игроках > N», базовый скин всегда, кейсы 3 / 100 / 500 / 1001 игроков, `nextSkin` ведёт к достижимой ступени |
| `lib/profile.test.ts` | длина, допустимые символы, резерв-лист, запрет `0x…`, регистронезависимый ключ уникальности |

Тесты гоняются в **прод-таймингах** (`GAME_MODE` в тест-окружении не выставлен) —
проверяется то, что поедет в прод, а не демо-режим.

Чего пока нет: API-роуты как целое (конкурентность файлового стора закрыта
`lib/store-file.test.ts`, для Prisma-стора нужна тестовая БД).

## E2E-скрипты (против запущенного `npm run dev`)

```bash
npm run test:auth                 # или node scripts/test-auth.mjs
node scripts/test-profile.mjs
BASE=http://localhost:3005 npm run test:auth    # другой порт
```

- **`scripts/test-auth.mjs`** — 7 проверок SIWE: валидный вход **и** отказы для чужого
  домена, чужого nonce, протухшей, битой и чужой подписи. Подписывает сообщения
  одноразовыми ключами из `viem/accounts` — реальные кошельки не участвуют.
- **`scripts/test-profile.mjs`** — сквозной профиль: 403 для анонима, установка ника,
  `nickname_taken`, невалидные значения, резерв-лист, приватность адреса в борде
  и отдельный кейс на **гонку за ник** (два клиента разом).

### Буст против настоящего чейна (`scripts/test-boost.mjs`)

Буст — единственное место, где игровая экономика зависит от внешнего состояния (баланс и
эмиссия токена on-chain). Юнит-тесты покрывают пороги и порядок применения, но не отвечают
на вопрос «сервер вообще умеет читать чейн и реагировать на изменения».

Кроме регрессии на эксплойт «вошёл с токеном → продал → стакаю с множителем», скрипт
проверяет саму **лестницу**: доминирует эмиссию админским минтом (иначе тестовый игрок
владеет ~100% mock-токена и попадает на вершину при любом балансе) и сверяет ступени на
настоящих долях, включая потолок для кита с половиной эмиссии. Пороги берутся импортом
из `lib/game.ts`, а не копией — иначе тест разошёлся бы с экономикой при первой калибровке.

Стенд (нужен Foundry):

```bash
anvil --port 8545 --chain-id 88991 --silent
```

Задеплоить mock-ERC20 с открытыми `mint`/`burn` (контракта нет в репозитории — это
одноразовый стенд: `balanceOf`, `decimals`, `mint`, `burn`, больше приложению ничего
не нужно):

```bash
forge create src/MockVLTR.sol:MockVLTR --rpc-url http://127.0.0.1:8545 \
  --mnemonic "test test test test test test test test test test test junk" --broadcast
```

Скрипт выводит тот же аккаунт из стандартной мнемоники anvil — сырых приватных ключей
в репозитории нет намеренно, их отвергает `npm run check:secrets`. Затем поднять dev
с теми же значениями сети:

```bash
NEXT_PUBLIC_RH_CHAIN_ID=88991 NEXT_PUBLIC_RH_RPC_URL=http://127.0.0.1:8545 \
NEXT_PUBLIC_VLTR_ADDRESS=<адрес> NEXT_PUBLIC_VLTR_BOOST_MIN=1 \
GAME_MODE=demo npx next dev -p 3100
```

```bash
BASE=http://localhost:3100 TOKEN_ADDRESS=<адрес> npm run test:boost
```

13 проверок: порог (0.5 / ровно 1), что буст доезжает до множителя (×1.2 → ×6), что
покупка после входа включает буст без перелогина, что аноним буста не получает, и
**главная регрессия** — продал токен, и следующий кранк перестал давать ×5.

Отдельно проверяется отказ сети: при погашенном anvil `/api/boost/refresh` возвращает
`stale: true` и **сохраняет** прежний буст, а кранк проходит с прежним множителем.
Иначе сетевой сбой молча снимал бы ×5 у честного холдера.

Проверять отказы так же важно, как успех: тест, который проверяет только happy path,
не заметит, что защита вообще отключилась.

## Сидер ботов

```bash
node scripts/seed-bots.mjs 239      # набить борд ботами (степенное распределение стека)
node scripts/seed-bots.mjs --clear  # убрать всех ботов
```

Нужен, чтобы потрогать гейтинг скинов: «TOP 100» включается только при >100 игроков,
без массовки это не проверить.

Гарантии честности:
- боты пишутся с префиксом `bot:` и на борде помечены тегом `test`;
- скрипт **отказывается работать при заданном `DATABASE_URL`** (то есть в проде);
- после сидинга нужен рестарт dev-сервера — файловый стор кэширует данные в памяти;
- перед реальным запуском обязательно `--clear`.

## Визуальные утилиты

```bash
node scripts/render-sprite.mjs out.png   # спрайт сейфа со страницы → PNG ×12 (nearest)
node scripts/render-skins.mjs out.png    # все 6 скинов одной полосой
```

Требуют запущенный dev-сервер и `sharp`. Появились потому, что в текущем preview-sandbox
не снимается растровый скриншот: DOM-дерево и computed styles читаются, capture — нет.
UI проверялся через DOM; для оценки пиксель-арта глазами — эти скрипты либо
`http://localhost:3000` в браузере.

## Локальная проверка петли целиком

```bash
GAME_MODE=demo npm run dev      # WIND 30с / GRACE 15с / BASE 5 вместо 24ч/12ч
```

Полный цикл (кранк → завод → окно → рейд) проходится за минуту. В проде переменную
не выставлять.
