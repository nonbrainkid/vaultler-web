# API

Все роуты: `app/api/**/route.ts`, `runtime = "nodejs"`, `dynamic = "force-dynamic"`.
Идентичность резолвится через `resolveIdentity(req)` (`lib/http.ts`): заголовок
`x-vaultler-id` от `proxy.ts` — **подписанный и проверяемый в роуте**, — фолбэк на
подписанную cookie, крайний случай — свежий эфемерный id.

Общие правила:
- клиентское время, стек и буст **не принимаются** ни одним эндпоинтом;
- любой мутирующий метод (POST) проверяет происхождение запроса:
  `403 { error: "bad_origin" }` для чужого `Origin`/`Sec-Fetch-Site: cross-site`;
- тело POST ограничено 16 КБ: `413 { error: "too_large" }`;
- `429 { error: "rate_limited" }` при срабатывании лимита (см. `lib/ratelimit.ts`);
- все ответы идут с `cache-control: private, no-store` и `vary: cookie` — они
  персональные и не должны оседать в общих кэшах;
- ответы не содержат internal id (`dev:uuid`, `wallet:0x…`) — наружу идёт только адрес,
  и только если игрок не скрыл кошелёк;
- ответы `/api/telegram/*` не содержат `chatId` ни при каких условиях — тот же инвариант,
  распространённый на привязку бота (`toLinkStatusView`, `lib/telegram-link.ts`).
- **исключение по origin**: `POST /api/telegram/webhook/[secret]` НЕ проверяет
  `sameOriginOk` — запрос приходит от Telegram, а не из браузера, у него нет `Origin` в
  принципе. Аутентификация там идёт секретом в пути и в заголовке
  `X-Telegram-Bot-Api-Secret-Token` (см. ниже). Это единственное, явно
  прокомментированное в коде исключение — `sameOriginOk()` в `lib/http.ts` не менялся.

## `GET /api/state`

Состояние игрока для отрисовки. **Read-only**: `settle` считается в памяти и не
персистится (стек детерминирован из таймстемпов), поэтому поллинг раз в 2.5 с дешёвый.

```jsonc
{
  "view": {                     // PublicView, см. game-mechanics.md
    "stack": 1234.5, "streak": 3, "multiplier": 1.6, "ratePerSec": 0.016,
    "phase": "winding",         // off | winding | ready | stall
    "tierIndex": 1, "tierName": "SAFE", "tierAt": 500,
    "gold": false, "nextTierAt": 2500, "nextTierName": "VAULT",
    "phaseEndsInMs": 42000, "serverNow": 1769000000000,
    "boost": true,              // тир холда > 0 (короткая проверка для UI)
    "holder":     { "level": 2, "name": "RANCHER", "mult": 2, "sharePct": 0.005 },
    "nextHolder": { "level": 3, "name": "OUTLAW", "mult": 2.75, "sharePct": 0.02 } | null,
    "holderSharePct": 0.0071,   // своя доля эмиссии на момент последнего чтения чейна
    "raidPreview": { "pct": 15, "amount": 185.2 }  // сколько заберёт рейдер, случись он сейчас
  },
  "raid": { "lost": 180.2 } | null,   // если игрок как раз проспал окно
  "wallet": "0x…" | null,             // адрес, если сессия привязана к кошельку
  "nickname": "egor" | null,          // свой ник (для редактора)
  "hideWallet": false                 // своя настройка приватности
}
```

## `POST /api/crank`

Единственный способ завести машину. Тела запроса нет.
Rate-limit: `allowCrank` — не чаще **1 раза в секунду на идентичность**.

Перед заводом сервер перечитывает баланс $VLTR и фиксирует буст на весь предстоящий
завод. Если RPC не ответил — прежнее значение сохраняется (`docs/web3.md`).

```jsonc
{ "ok": true, "reason": null, "raid": null, "view": { … } }
{ "ok": false, "reason": "winding", "raid": null, "view": { … } }   // завод ещё идёт
```

`ok: false` — это **200**, а не ошибка: сервер сообщает, что фаза не позволяет кранк.

## `GET /api/leaderboard`

Недельный борд и общий сейф. Считается по живому стеку (каждому `settle` на now).

```jsonc
{
  "communalVault": 918273.4,          // сумма живых стеков всего комьюнити
  "players": 240,
  "top": [{
    "rank": 1, "label": "egor",       // ник / короткий адрес / "anon" / имя бота
    "kind": "wallet",                 // wallet | anon | bot
    "address": "0x…" | null,          // null, если игрок скрыл кошелёк
    "stack": 40123.7, "streak": 12, "isYou": false,
    "eligible": true,                 // подтверждённый кошелёк — может получить выплату
    "moneyRank": 1 | null             // место в призовой зоне; НЕ равно rank
  }],
  "you": { "rank": 57, "stack": 812.3, "eligible": false, "moneyRank": null } | null,
  "week": { "weekId": 133, "endsInMs": 259200000 },
  "payoutSeats": 10                   // сколько мест в деньгах — клиент не хардкодит
}
```

**`moneyRank` ≠ `rank`.** Ранг — место в гонке, его занимает любой игрок. Призовые места
считаются по первым `payoutSeats` **подтверждённым кошелькам** с ненулевым приростом:
анонимной сессии токены отправить некуда, а завести её можно бесплатно в один клик
(на проде 2026-07-28 шесть из десяти верхних строк были именно такими). Аноним остаётся
в общем зачёте и виден на борде — иначе ему нечем измерить, что он теряет.

Из-за этого **число строк в `top` плавающее**: список дотягивается до последнего призового
места (потолок — `limit + payoutSeats`). Обрезав его ровно по десятой строке, борд
подсвечивал бы «в деньгах» тех, кому не платят, и прятал тех, кому платят.

`snapshot()` тянет всех игроков — на масштабе нужна пагинация или материализованный топ
(см. `NOTES.md`).

## `POST /api/profile`

Ник и приватность адреса. Только для сессии с **подтверждённым кошельком** —
у анонимов личность = кука, которую легко сбросить, что открыло бы сквот ников.

```jsonc
// запрос: любое подмножество полей
{ "nickname": "egor" }     // "" или null — очистить ник
{ "hideWallet": true }
// успех
{ "ok": true, "nickname": "egor", "hideWallet": false, "view": { … } }
```

| Код | `error` | Причина |
|---|---|---|
| 403 | `wallet_required` | анонимная сессия |
| 400 | `too_short` / `too_long` / `bad_chars` / `reserved` / `bad` | валидация (`lib/profile.ts`) |
| 400 | `bad_body` / `nothing_to_update` | нет валидного JSON или нечего менять |
| 409 | `nickname_taken` | ник занят (включая гонку — Prisma P2002) |
| 429 | `rate_limited` | `allowProfile`, 30/мин на IP |

## `GET /api/auth/nonce`

Одноразовый nonce для SIWE. Кладётся в **httpOnly-cookie** `vaultler_nonce`
(TTL 5 мин) и дублируется в теле `{ "nonce": "…" }`.
Rate-limit: `allowNonce`, 40/мин на IP.

## `POST /api/auth/verify`

Проверка SIWE-подписи → идентичность = адрес кошелька.

```jsonc
// запрос
{ "message": "<SIWE EIP-4361 текст>", "signature": "0x…" }
// успех: ставит cookie сессии, гасит nonce
{ "ok": true, "address": "0x…", "view": { … } }
```

| Код | `error` | Что не сошлось |
|---|---|---|
| 400 | `bad_body` / `bad_params` | не JSON, сообщение >2000 симв., подпись не hex или >4096 симв. |
| 400 | `nonce_missing` / `bad_message` | нет cookie с nonce, или адрес в сообщении невалиден |
| 401 | `message_rejected` | домен, nonce, версия, `uri` или срок действия не сошлись. Срок обязателен и не длиннее 5 мин (+2 мин на расхождение часов) |
| 401 | `bad_signature` | подпись не принадлежит адресу из сообщения |
| 403 | `bad_origin` | запрос пришёл с чужого сайта |
| 413 | `too_large` | тело больше 16 КБ |
| 429 | `rate_limited` | `allowAuth`, 30/мин |
| 500 | `server_misconfigured` | не задан `AUTH_DOMAIN` в проде — проверять подпись не против чего |

Отдаём `address`, а не `identity`: формат внутреннего id — деталь хранилища,
и в публичном контракте API ей не место.

Детали проверок — `docs/auth-session.md`.

## `POST /api/auth/logout`

Гасит cookie сессии. На следующем запросе `proxy.ts` заведёт свежую анонимную
dev-сессию — играть можно и без кошелька. Ответ: `{ "ok": true }`.

## `POST /api/boost/refresh`

Перечитать баланс и эмиссию $VLTR on-chain и обновить тир холда для текущего кошелька.
Для анонимной сессии — no-op с `boost: false`. Клиент тир не задаёт никогда.

Ответ: `{ "boost": true, "stale": false, "holderBalance": "12500.0",
"toNextTier": "37500.0", "view": { … } }`.

- `stale: true` — RPC не ответил, прежний тир сохранён (значение не подтверждено);
- `holderBalance` / `toNextTier` — **свой** баланс и сколько токенов не хватает до
  следующей ступени (`null` на вершине). Чужие балансы наружу не отдаются никогда.

`stale: true` — баланс прочитать не удалось (RPC молчит). Прежний буст при этом
**сохраняется**, а не сбрасывается: сетевой сбой не должен снимать множитель у холдера.
UI показывает такое значение как неподтверждённое.

Rate-limit: `allowBoost`, не чаще раза в 10 с на игрока. Каждый вызов — обращение
к RPC от нашего имени; без интервала один вошедший игрок прокачивал бы через нас
неограниченный поток к провайдеру. На 429 клиент оставляет экран как есть и не
показывает баннер «нет связи» — связь есть, просто рано.

Буст пересчитывается также на `POST /api/crank` — там он фиксируется на весь завод
(`docs/web3.md`). Этот эндпоинт нужен, чтобы увидеть новую ступень сразу после покупки, не дожидаясь
следующего кранка.

## `GET /api/health`

Health-check для мониторинга и проверки после деплоя. Секретов не отдаёт.

```jsonc
{ "ok": true, "ts": 1769000000000,
  "checks": { "store": "postgres" | "file" | "error",
              "weekResults": "ready" | "missing",
              "sessionSecret": "set" | "default",
              "chain": "configured" | "placeholder",
              "rateLimit": "shared" | "memory" } }
```

`503`, если стор не отвечает или нет таблицы `WeekResult`.

`weekResults: "missing"` = миграция не выполнена (`npx prisma db push`). Обращение к этой
таблице случается впервые **в субботу в полночь**, внутри транзакции кранка: без миграции
отвалится не запись результата, а сам кранк — игра встанет в день выплаты. Поэтому проверка
вынесена в health, а не оставлена «на заметить».

`rateLimit: "memory"` означает, что счётчики лимитов живут в памяти инстанса и на
serverless обходятся размазыванием запросов. Перед раздачей реальных призов здесь
должно быть `"shared"` (подключён Vercel KV / Upstash).

## `POST /api/admin/close-week`

Финализация завершённой недели: кто с каким приростом её закончил, кому какое призовое
место и какая доля пула. **Денег не отправляет** — готовит список для ручной выплаты.

Доступ — по общему секрету `ADMIN_SECRET` (≥16 симв.), а не по сессии: роут дёргает cron
или человек из терминала, браузерной сессии там нет. Секрет сверяется по SHA-256 обеих
сторон через `timingSafeEqual`: прямое сравнение строк выходит из цикла на первом
несовпавшем символе и выдаёт секрет по времени ответа.

```bash
curl -X POST https://thevaultler.fun/api/admin/close-week \
  -H "authorization: Bearer $ADMIN_SECRET" \
  -H "content-type: application/json" \
  -d '{"dryRun":true}'
```

Удобнее — обёртка: `ADMIN_SECRET=… npm run close:week -- --dry` (`scripts/close-week.mjs`).

```jsonc
// запрос: оба поля необязательны
{ "weekId": 2951,      // по умолчанию — предыдущая неделя
  "dryRun": true }     // посчитать и показать, ничего не записывая

// ответ
{ "ok": true, "dryRun": false, "weekId": 2951,
  "participants": 33, "seats": 4,
  "payouts": [{ "rank": 1, "address": "0x…", "gain": 2073, "share": 0.4, "sharePct": 40 }],
  "notEligible": 6 }   // играли, но получить не могут — метрика для community-работы
```

Идемпотентен: повторный прогон не задваивает участника (`@@unique([weekId, identity])`)
и не стирает уже вписанный вручную `payoutTx`.

| Код | `error` | Причина |
|---|---|---|
| 401 | `unauthorized` | нет или неверный `Bearer`-секрет |
| 400 | `week_not_finished` | попытка закрыть текущую или будущую неделю |
| 400 | `bad_body` / `too_large` | не JSON или тело больше 16 КБ |
| 503 | `admin_secret_missing` | `ADMIN_SECRET` не задан — роут отключён |

Наружу отдаются только адреса: internal id (`wallet:0x…`) не уходит даже админскому
клиенту, чтобы формат идентичности не расползался по скриптам и логам.

## `GET /api/telegram/link`

Статус привязки Telegram-напоминаний текущей сессии (аноним или кошелёк — оба варианта
поддерживаются одинаково). Фича за флагом: без `TELEGRAM_BOT_TOKEN` +
`TELEGRAM_WEBHOOK_SECRET` + `CRON_SECRET` разом отвечает `configured: false`, ничего не
падает (docs/deployment.md).

```jsonc
{ "configured": true, "linked": false }
```

`chatId` не отдаётся НИКОГДА, даже владельцу привязки — только производный `linked`
(тот же инвариант 5, что и для `wallet:0x…`/`dev:uuid`). Покрыто `lib/telegram-link.test.ts`
(`toLinkStatusView`).

## `POST /api/telegram/link`

Выдать одноразовый код привязки владельцу текущей сессии. Сама привязка происходит
НЕ здесь, а когда игрок отправляет боту `/start <код>` — см. вебхук ниже.

```jsonc
{ "ok": true, "code": "a1b2…(32 hex)", "expiresInSec": 600 }
```

Username бота в ответе не передаётся: клиент собирает deep link из константы
`TELEGRAM_BOT_USERNAME` (`lib/links.ts`) — той же, что и ссылка «REMINDER BOT» в шапке
сайта, чтобы обе никогда не разошлись.

| Код | `error` | Причина |
|---|---|---|
| 403 | `bad_origin` | запрос с чужого origin |
| 429 | `rate_limited` | `allowTelegramLink`, 5 / 10 мин на identity |
| 503 | `not_configured` | бот выключен (не заданы все три env) |

## `POST /api/telegram/unlink`

Кнопка отписки на сайте. Физически удаляет привязку (не флаг) — тот же метод стора, что
и команда `/stop` в боте. Идемпотентно: без активной привязки просто отвечает `linked: false`.

```jsonc
{ "ok": true, "linked": false }
```

## `POST /api/telegram/webhook/[secret]`

Приём апдейтов от Telegram. Самое уязвимое место всей фичи (docs/brief-engineer.md) —
защищено ДВОЙНО: случайный секрет в самом пути **и** заголовок
`X-Telegram-Bot-Api-Secret-Token`, сверяемый с тем же секретом через `timingSafeEqual`.
Несовпадение любого из двух → `404` (не `401`/`403` — код ответа не должен подсказывать,
что путь угадан почти верно).

Инвариант 8 (`sameOriginOk` на каждом POST) здесь осознанно не применяется: у запроса от
Telegram нет `Origin` — аутентификация идёт секретом, а не происхождением (см. комментарий
в самом роуте).

Команды: `/start <код>` (привязка, только из приватного чата — иначе игровые данные
поехали бы в чужую группу), `/stop` (отписка). Дедуп по `update_id` — повторная доставка
одного и того же апдейта (Telegram ретраит) не обрабатывается дважды. Ответ всегда `200`,
если тело в принципе распарсилось, — Telegram не должен ретраить из-за бизнес-логики
(неверный код, чужая группа и т.п.).

## `POST /api/telegram/remind`

Рассылка напоминаний «окно открылось» / «2 часа до рейдера». Триггерится расписанием
**GitHub Actions** (`.github/workflows/reminders.yml`), не Vercel Cron: план Hobby
ограничивает крон Vercel разом в сутки — непригодно для двухчасового окна, а более частое
расписание в `vercel.json` на Hobby ломает сам деплой (докладная — docs/deployment.md).

Защита — `Authorization: Bearer <CRON_SECRET>`, сверяется `timingSafeEqual` (тот же
паттерн, что `close-week`).

```bash
curl -X POST https://thevaultler.fun/api/telegram/remind \
  -H "authorization: Bearer $CRON_SECRET"
```

```jsonc
{ "ok": true, "due": 4, "sent": 3, "skippedDuplicate": 1, "unlinkedBlocked": 0, "failed": 0 }
```

Момент считается ТОЛЬКО из серверного стейта (`lastCrankAt` + тайминги `lib/game.ts`),
`settle()` — только в памяти, ни одного `store.mutate` в этом роуте нет: бот не мутирует
игровой стейт. Идемпотентность — `(identity, lastCrankAt, kind)`, поэтому повторный или
запоздавший тик планировщика не задваивает сообщение. `unlinkedBlocked` — сколько привязок
удалено автоматически из-за 403 «bot was blocked by the user».

| Код | `error` | Причина |
|---|---|---|
| 401 | `unauthorized` | нет или неверный `Bearer`-секрет |
| 503 | `not_configured` | бот выключен |

## Чего в API нет (и почему)

- **Нет эндпоинта, задающего стек/стрик/буст.** Любой такой роут = дырка в призовой пул.
- **Нет выплат.** Пул платится вручную вне сайта, кастодии нет (`docs/leaderboard-rewards.md`).
  `close-week` только считает, кому и сколько причитается.
- **Нет админки для правки данных.** Правки — только напрямую в БД, осознанно.
