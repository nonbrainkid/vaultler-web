# THE VAULTLER

Мем-токен + ежедневный минигейм на Robinhood Chain (Arbitrum Orbit L2).
Заводишь машину (CRANK) — она стакает $STACK, пока ты спишь. Вернулся в окно —
стрик и множитель растут (компаунд). Проспал — приходит рейдер и скимит стек.
Вайб: анти-трейдинг, про-стакинг. Пиксель-вестерн.

> **Не финансовый совет. Никакой кастодии средств. Только wallet-connect (чтение баланса + подпись для входа).**

## Главный принцип: сервер — источник правды
Стек, стрики и тайминги кранка считаются и хранятся **на сервере** (`lib/game.ts` + API).
Клиент только рисует. Лидерборд раздаёт реальные токены — если бы состояние жило в браузере,
любой накрутил бы себе топ. Подробности и решения — в [NOTES.md](NOTES.md).

## Стек
Next.js 16 (App Router) · TypeScript · Prisma (Postgres) · wagmi + viem · plain CSS (пиксель-арт).

## Запуск локально
```bash
npm install
cp .env.example .env.local          # заполнять не обязательно для локали
npm run dev                         # http://localhost:3000
# быстрый демо-цикл петли (30с/15с вместо 24ч/12ч):
GAME_MODE=demo npm run dev
```
Без `DATABASE_URL` используется файловый стор (`.data/players.json`) — БД не нужна для разработки.

## Тесты
```bash
npm test          # юнит-тесты ядра механики (lib/game.ts)
```

## Безопасность репозитория

Репозиторий **приватный**. Перед каждым пушем прогоняется аудит:

```bash
npm run check:secrets
```

Он проверяет и рабочее дерево, и **всю историю коммитов** (при пуше уходят все коммиты,
и секрет, удалённый следующим коммитом, всё равно остаётся в git): запретные файлы
(`.env`, `.data/`, ключи, `node_modules`, сгенерированный Prisma-клиент), паттерны
секретов (приватные ключи, токены, строки подключения с паролем) и покрытие `.gitignore`.

Аудит подключён как git-хук и запускается автоматически:

```bash
git config core.hooksPath .githooks   # выполнить один раз после клона
```

**Правила:**
- Никаких реальных значений в `.env.example` — только пустые плейсхолдеры.
- Секреты живут в `.env.local` (локально) и в env-переменных Vercel (прод).
- `SESSION_SECRET` в проде обязателен: без него приложение намеренно падает,
  иначе подпись сессионных cookie шла бы публично известным ключом из репозитория.
- Перед реальным запуском убрать тестовых ботов: `node scripts/seed-bots.mjs --clear`.

## Деплой на Vercel — пошагово (runbook)

Код готов к деплою. Нужны только твой аккаунт Vercel и реальные значения сети/токена.

1. **Проект.** Vercel → Add New → Project → импортировать `vaultler-web`. Framework
   определится как Next.js. Build/Output — по умолчанию (`npm run build` уже включает
   `prisma generate`).
2. **База.** Vercel → Storage → Create → **Postgres** → привязать к проекту. Он сам
   проставит `DATABASE_URL` в env проекта.
3. **Env** (Project → Settings → Environment Variables), см. `.env.example`:
   - `SESSION_SECRET` — **обязательно**. Сгенерировать: `openssl rand -base64 32`.
     Без него прод намеренно падает (защита от подделки сессий).
   - `AUTH_DOMAIN` — домен сайта без схемы (напр. `vaultler-web.vercel.app` или свой).
   - `NEXT_PUBLIC_SITE_URL` — полный URL (для OG/sitemap/robots).
   - `NEXT_PUBLIC_RH_*` и `NEXT_PUBLIC_VLTR_*` — реальные chainId/RPC/адрес токена,
     когда будут (до этого буст просто не активируется, играть можно).
   - НЕ выставлять `GAME_MODE` и `DEV_FORCE_BOOST` в проде.
4. **Схема БД.** Один раз, с прод `DATABASE_URL` в окружении:
   ```bash
   npx prisma db push
   ```
5. **Деплой.** Push в `main` (или Deploy в UI). После деплоя проверить:
   ```bash
   curl https://<домен>/api/health      # {"ok":true, store:"postgres", sessionSecret:"set"}
   ```
6. **Перед публичным запуском:** `node scripts/seed-bots.mjs --clear` (если гонял ботов
   на общей БД), и включить общий rate-limit стор (Upstash/Vercel KV) — см. NOTES.md.
