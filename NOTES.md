# VAULTLER — журнал решений

Здесь только **решения с датами и открытые вопросы** — «почему сделано именно так».
Описание того, **как это работает**, живёт в [docs/](docs/) (указатель — в
[CLAUDE.md](CLAUDE.md)), чтобы не читать одно и то же дважды.

---

## Решения

### 2026-07-23 — фундамент
- **Дизайн:** пиксель-вестерн, как на артах X @VaultlerRH, а не латунный прототип.
  Механика прототипа (`reference/vaultler-minigame.html`) — эталон, визуал перерисован.
- **БД:** Vercel Postgres сразу, Prisma как ORM (`provider = postgresql`).
  Локально — файловый стор, чтобы не требовать БД для разработки → `docs/data-store.md`.
- **Прод-тайминги петли:** 24ч завод + 12ч grace на перекранк.
- **Сервер — источник правды.** Вся математика петли на сервере, клиент только рисует.
  В прототипе стейт жил в `window.storage` — любой мог выставить `S.total = 999999`
  через DevTools и украсть призовой пул → `docs/architecture.md`, `docs/security.md`.
- **Идентичность:** временная серверная сессия (подписанная cookie), в M2 заменена
  входом кошельком. Cookie ставится в `proxy.ts` на навигационном ответе, а не через
  fetch: некоторые браузеры (и preview-sandbox) не сохраняют `Set-Cookie` из fetch,
  плюс это чинит гонку двойного минта в dev-StrictMode → `docs/auth-session.md`.
- **`SESSION_SECRET` в проде обязателен**: дефолт публично известен из репозитория,
  зная его можно подделать чужую сессию. Без секрета прод намеренно падает.

### 2026-07-24 — кошелёк, лендинг, готовность к запуску
- **Вход кошельком — полноценный SIWE / EIP-4361** через `viem/siwe` (аудированные
  примитивы вместо своего парсера). Проверяем домен, одноразовый nonce, срок 5 мин,
  подпись. `AUTH_DOMAIN` пинит домен в проде, потому что `Host` можно подделать.
- **connectkit не взяли** — несовместим с React 19; своя кнопка и модалка в теме проекта.
  WalletConnect/Coinbase SDK не тянем, пока нет `projectId`.
- **Буст ставит сервер**, читая баланс on-chain: клиентский флаг позволил бы не-холдеру
  получить множитель → `docs/web3.md`.
- **Строгий CSP с per-request nonce** (`proxy.ts`) — главный барьер против внедрения
  дрейнер-скрипта через XSS. Лендинг переведён в `force-dynamic`: статический HTML
  не может получить per-request nonce. В dev CSP ослаблен (Turbopack HMR требует eval).
  В `next.config.ts` остались только базовые заголовки — сам CSP живёт в `proxy.ts`.
- **Гейтинг скинов по размеру комьюнити** (решение Егора): «TOP N» включается только
  когда игроков больше N, иначе при 50 участниках в «топ-100» попадают все и награда
  обесценивается. Потолок едет вверх вместе с комьюнити → `docs/design.md`.
- **Копирайтинг-гардрейлы:** fair launch → никакой токеномики по бакетам, не держим
  средства пользователей, нигде не обещаем APY цифрой. Секция «WHAT WE DO NOT DO»
  проговаривает это явно → `docs/frontend.md`.
- **Боты помечаются `bot:` и тегом `test`**, сидер отказывается работать при заданном
  `DATABASE_URL`: борд будет делить реальные токены, неотличимые фейки недопустимы.

### 2026-07-25 — экономика наград v2
Проблема: нет ликвидности, чтобы залить призовой пул заранее → наполняем от фисов.
- **Буст холда ×5** (было ×1.5). Большой множитель намеренный: без холда в топ-10
  практически не попасть → двигатель покупок → объёма → фисов.
- **Пул = 50% от 7% торговых фисов**, делит **топ-10 игрового борда** по `$STACK`.
- **Выплаты вручную раз в неделю, вне сайта.** Сайт показывает пул, зону выплат и
  победителей; токены отправляет команда. Никакой кастодии → аудит контракта не нужен.
- **Юр-рамка:** платим за МЕСТО В ИГРЕ (приз за скилл), а не пропорционально холду
  (дивиденд). «Top 10 holders get fees» ближе к секьюрити; «top 10 players» безопаснее.
  Показать юристу перед запуском токена → `docs/leaderboard-rewards.md`.

### 2026-07-25 — профиль: ники и приватность адреса
- **Ник только с подтверждённым кошельком** (403 для анонимов): у анонима личность —
  кука, которую легко сбросить, то есть сквот ников был бы бесплатным.
- Запрет ников, начинающихся с `0x` — иначе ник маскируется под адрес, а на борде
  рядом стоят настоящие адреса. Плюс резерв-лист (`admin`, `team`, `vaultler`…).
- **Адрес на борде открыт по умолчанию** — прозрачность: люди проверяют, реальным ли
  кошелькам уходят выплаты. Скрыть можно, тогда адрес не уходит наружу вообще.
  В UI честно сказано, что это не прячет on-chain историю → `docs/auth-session.md`.
- Гонка за ник закрыта на обоих сторах (Prisma ловит P2002 → чистый 409; файловый стор
  сериализует все `setProfile` глобально) → `docs/data-store.md`.

### 2026-07-25 — документация разложена по частям
- Описание «как работает» вынесено из NOTES.md и README в [docs/](docs/) — по одному
  файлу на часть проекта (архитектура, механика, API, стор, вход, безопасность, дизайн,
  фронтенд, web3, борд, тесты, деплой). `CLAUDE.md` (≤200 строк) держит обзор,
  инварианты и указатель «в каком файле что» — чтобы не читать лишнее ради контекста.
- NOTES.md остался журналом решений (на него ссылаются комментарии в коде).
- Заодно синхронизированы отставшие комментарии: буст ×1.5 → ×5 (`.env.example`,
  `lib/vltr.ts`, `lib/chain.ts`), CSP в `next.config.ts`, `middleware.ts` → `proxy.ts`
  в `lib/http.ts` и `lib/session.ts`, пометка «`CrankLog` пока не пишется» в схеме.

### 2026-07-25 — подготовка к деплою: лимиты, аудит кранков, чистый прод-бандл
- **Rate-limit переехал в общий стор** (Vercel KV / Upstash по REST, `lib/kv.ts`).
  Причина — атака, которую память процесса не ловит вообще: на serverless инстансов
  много, запросы размазываются, и каждый попадает в свежий счётчик. Лимита фактически
  не было. Взяли REST, а не ioredis: TCP-соединение не переживает инстанс, а пул
  подключений на холодных стартах выедает лимит Redis.
- **Окно фиксированное, не скользящее.** `INCR`+`EXPIRE` атомарны и стоят один
  round-trip; скользящее окно потребовало бы Lua или нескольких команд. Плата — на стыке
  окон теоретически проходит до 2× лимита, это заложено в бюджеты.
- **Фолбэк в память при недоступном Redis, а не отказ.** Лимитер защищает от флуда,
  а не от денежной операции: сам кранк валидируется фазой в `lib/game.ts`. Ронять сайт
  из-за Redis дороже, чем на время ослабить анти-флуд. Что активно — видно в
  `/api/health` → `rateLimit`.
- **Env не заданы → лимитер молча работает в памяти.** Поэтому статус вынесен в health:
  иначе «подключить KV» — незаметно пропускаемый шаг, и о нём вспомнили бы после раздачи
  призов, а не до.
- **`CrankLog` начал писаться** — в той же транзакции, что и стейт. Отдельная запись
  разошлась бы со стейтом при падении между ними и перестала бы быть доказательством.
  Добавлены `stack` и `lostToRaid`: без них спор «у меня было больше» не разобрать.
- **Журналим только успешные кранки.** Отклонённые (фаза `winding`) стейт не меняют —
  спорить не о чем, — а клиент, поллящий кранк, при лимите 1/сек нагенерил бы до 86 400
  строк в сутки на игрока.
- **Импорт `FileStore` закрыт условием `NODE_ENV !== "production"`.** Условие статически
  вычислимо, поэтому прод-сборка вырезает ветку вместе с `fs`/`path`. Build-варнинг
  «whole project traced» это НЕ убрало — он идёт от клиента Prisma (см. «Известные issues»).

### 2026-07-25 — коннект кошелька: молчаливый отказ
- **Баг:** клик по кошельку, которого нет в браузере, закрывал модалку без единого слова.
  Причина — `connect` из `useConnect()` не реджектит промис (ошибка уходит в состояние
  хука), поэтому `await connect()` проходил всегда, `setOpen(false)` срабатывал
  безусловно, а `catch` с текстом ошибки был мёртвым кодом. Перешли на `connectAsync`
  и закрываем модалку только по факту успеха.
- **Ошибки сверяем по `name`/`code`, а не по тексту** — текст локализуется кошельком
  и меняется между версиями. Идём по всей цепочке `cause`: wagmi и кошельки оборачивают
  исходную ошибку.
- **«Кошелёк не найден» — отдельное сообщение.** Это самая частая причина неудачи,
  и без явного текста пользователь видит, что «ничего не произошло», и уходит.
- Проверено на живой странице: три коннектора дают корректные сообщения, модалка
  остаётся открытой; успешный путь снят через подставной EIP-6963-провайдер —
  коннект проходит, модалка закрывается, UI переходит в `SIGN IN`, `nonce` → 200,
  `verify` → 401 на подложную подпись.

### 2026-07-25 — холдерский буст: дыра в экономике
- **Баг (главный):** буст писался ТОЛЬКО при входе. Схема обхода: войти с одним токеном,
  тут же продать его — и стакать ×5 бесконечно, забирая недельный пул, ничего не холдя.
  Это ломало сам двигатель проекта («холди, чтобы попасть в топ-10»). Зеркально: купивший
  токен после входа не получал буст, пока не перелогинится.
- **Решение — пересчёт на кранке.** Кранк фиксирует ставку на следующие 24 часа, значит
  и проверять владение надо именно там: держи токен в момент завода. Плюс кнопка
  RE-CHECK, чтобы увидеть ×5 сразу после покупки (эндпоинт `/api/boost/refresh`
  существовал, но клиент его не вызывал ни разу — был мёртвым кодом).
- **Буст применяется строго ПОСЛЕ `settle`.** Иначе включение ×5 задним числом
  пересчитало бы уже отработавший завод — игрок получил бы пятикратное начисление
  за сутки, которые стакал без токена.
- **Читаем баланс не на каждой попытке кранка.** Во время `winding` кранк отклоняется,
  а RPC-чтение при лимите 1/сек дало бы до 86 400 запросов в сутки на игрока. Сначала
  дешёвое чтение стейта, в сеть идём, только если кранк может пройти.
- **«Не смог прочитать» ≠ «баланс нулевой».** Раньше при ошибке RPC возвращался `0`,
  и честный холдер молча терял ×5 из-за сетевого сбоя. Теперь `computeBoost` отдаёт
  `null`, а вызывающий код сохраняет прежнее значение. В ответе — `stale: true`.
- **Порог сравнивается в bigint**, `boostMin` хранится строкой: перевод в `Number` терял
  точность уже на десятых долях токена при 18 decimals. `decimals` читается с контракта
  (env — фолбэк): рассинхрон сдвинул бы порог на порядки.
- **`tsconfig` target ES2017 → ES2020** — минимум для bigint-литералов. При `noEmit`
  влияет только на проверку типов, эмитом занимается SWC.
- Проверено e2e против настоящего чейна (anvil + mock-ERC20), 13/13, включая регрессию
  на сам эксплойт → `npm run test:boost`, рецепт в `docs/testing.md`. Отказ сети проверен
  отдельно: при погашенном anvil буст сохраняется, кранк проходит с прежним множителем.

## Открытые вопросы

- [ ] **Баланс прода:** `BASE_RATE_PER_SEC` и пороги тиров — плейсхолдеры под 24ч-петлю.
      Определиться, сколько стека даёт «идеальная неделя».
- [ ] **Куда идёт вторая половина фисов** (байбек / ликвидность / казна) — решение Егора.
- [ ] **Как именно делится пул** между местами 1–10 и сбрасывается ли счёт еженедельно.
      Сейчас ранжирование по накопленному стеку, не по приросту за неделю.
- [ ] **Robinhood Chain:** реальные chainId / RPC URL / explorer и адрес $VLTR
      (доки отложены — в коде плейсхолдеры, см. `lib/chain.ts`).
- [ ] **Подключить Vercel KV / Upstash** и выставить `KV_REST_API_URL`/`KV_REST_API_TOKEN`.
      Код лимитера готов, но без env он откатывается в память процесса — проверять по
      `/api/health` → `rateLimit: "shared"`.
- [ ] **Анти-мультиаккаунт:** политика при смене кошелька, привязка device/IP.
- [ ] **Ротация `CrankLog`:** журнал пишется бессрочно, на объёме понадобится удаление
      записей старше N месяцев.
- [ ] **Вернуть генератор Prisma в `node_modules`** (убрать `output` из схемы), чтобы
      сработало `serverExternalPackages` и перестал раздуваться бандл serverless-функции.
      Трогает слой данных — делать после запуска, с прогоном против прод-БД.
- [ ] **ERC-1271** (смарт-контрактные кошельки) — нужен рабочий RPC.
- [ ] **`snapshot()` тянет всех игроков** — на масштабе нужна пагинация или
      материализованный топ.
- [ ] **Vercel Postgres:** подключить проект и получить `DATABASE_URL` (локаль + прод).

## Известные issues

- `npm audit`: 3 уязвимости в транзитивных `postcss`/`sharp` из Next 16. Автофикс
  откатывает Next до 9.x (неприемлемо). Наш код не затронут, ждём патч апстрима.
- Build-варнинг Turbopack «whole project traced». 25.07 выяснено, что источник — **не**
  `FileStore` (так считалось раньше и это было записано в NOTES ошибочно), а
  сгенерированный клиент Prisma: `output` в схеме указывает на `lib/generated/prisma`,
  то есть путь внутри проекта, а не пакет в `node_modules`, и `serverExternalPackages`
  (принимает только имена пакетов) к нему не применяется. Лечение — вернуть генератор
  в `node_modules`; трогает слой данных, поэтому после запуска → `docs/deployment.md`.
- **Dev-ловушка:** после долгой сессии правок HMR плодит экземпляры `lib/store.ts`,
  у каждого своя копия `.data/players.json` в памяти → роуты начинают расходиться
  в показаниях. Лечится перезапуском `npm run dev`; в прод не переносится (Prisma
  состояния в памяти не держит) → `docs/data-store.md`.
- Растровый скриншот не снимается в текущем preview-sandbox (DOM и computed styles
  читаются, capture — нет). UI проверялся через DOM; для глаз — `scripts/render-*.mjs`
  или `http://localhost:3000`.
