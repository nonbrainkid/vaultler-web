# VAULTLER — рабочие заметки

Живой журнал решений и открытых вопросов. Обновляется по ходу майлстоунов.

## Стек
- Next.js 16 (App Router) + TypeScript, plain CSS (без Tailwind — нужен точный контроль над пиксель-артом).
- БД: **Vercel Postgres** (решено 2026-07-23). Prisma как ORM.
- Кошелёк (M2): wagmi + viem + connectkit. Сеть — Robinhood Chain (Arbitrum Orbit L2).
- Деплой: Vercel. Репо: git, ветка `main`.

## Решения (2026-07-23)
- **Дизайн:** пиксель-вестерн, как на странице X @VaultlerRH (не латунный прототип). Механика прототипа — эталон, визуал перерисовываем в пиксель-стиле.
- **БД на M1:** Vercel Postgres сразу (Prisma `provider = postgresql`).
- **Grace-окно (прод):** 24ч завод + 12ч grace на перекранк.
- **Идентичность на M1:** временная серверная сессия (подписанная cookie с dev-id).
  В M2 заменяется на авторизацию подписью кошелька (SIWE-стиль). «Один аккаунт = один кошелёк» доводим в M2.

## Критическое правило: сервер — источник правды
Стек/стрик/тайминги считаются и хранятся на сервере. Клиент только рисует.
Причина: лидерборд раздаёт реальные токены. В прототипе стейт жил в `window.storage` —
любой мог выставить `S.total = 999999` через DevTools и украсть призовой пул.
Вся математика петли — в `lib/game.ts` (чистые функции) + API-роуты, время серверное.

## Механика (из reference/vaultler-minigame.html)
- CRANK → завод на WIND, машина стакает по ставке. Во время завода кранк запрещён.
- После завода окно GRACE: успел крутануть → streak+1; проспал WIND+GRACE → рейд (skim %), streak→0.
- `mult = (1 + streak*0.2) * (boost ? 1.5 : 1)`; `rate = BASE * mult`.
- Тиры по стеку: Tin Can(0) → Safe(500) → Vault(2500) → Fort(10k) → Gold Reserve(50k).
- Буст ×1.5 за холд $VLTR (M2, читается on-chain).

### Демо-режим
`GAME_MODE=demo` в env → сжатые тайминги (WIND 30с / GRACE 15с / BASE 5) как в прототипе,
чтобы тестировать петлю быстро. В проде переменная не выставляется → 24ч/12ч.

## Идентичность / сессия (реализовано)
- Сессия ставится в `proxy.ts` (Next 16 middleware→proxy) на НАВИГАЦИОННОМ ответе,
  а не через fetch. Причина: некоторые браузеры (и наш preview-sandbox) не сохраняют
  Set-Cookie из fetch-ответов; навигационные куки сохраняются везде. Заодно чинит гонку
  двойного минта идентичности при dev-StrictMode.
- Идентичность прокидывается в роут заголовком `x-vaultler-id` (proxy → route), cookie
  подписана HMAC-SHA256 (Web Crypto, edge+node). Клиент не подделает чужой id.

## Экономика наград v2 (решено 2026-07-25)
Проблема: нет ликвидности, чтобы залить призовой пул заранее → наполняем его от фисов.
- **Буст холда $VLTR: ×5** (было ×1.5). Не-холдер стакает ×1. Стрик-компаунд сверху.
  Большой ×5 намеренный: без холда в топ-10 практически не попасть → двигатель покупок.
- **Пул = 50% от 7% торговых фисов.** Делит **топ-10 игрового лидерборда** (по $STACK).
- **Выплаты вручную раз в неделю**, вне сайта. Сайт показывает пул/победителей/зону выплат
  (топ-10 «in the money»), деньги команда шлёт сама. **Никакой кастодии, аудит не нужен.**
- **Юр-рамка (важно):** платим за МЕСТО В ИГРЕ (приз), а не пропорционально холду (дивиденд).
  «Top 10 holders get fees» = ближе к секьюрити; «top 10 players» = приз за скилл, безопаснее.
  Холд даёт ×5, поэтому топ и так из холдеров — но формально это игровой приз. Показать юристу.
- Тексты обновлены: Hero/HowItWorks/$VLTR/Trust/FAQ/футер/лидерборд + FAQ «это дивиденд? — нет».
- Открытый вопрос: куда идёт вторая половина фисов (байбек/ликвидность/казна) — решить Егору.

## Готовность к запуску (сделано автономно 2026-07-24)
- **CSP с nonce (прод):** `proxy.ts` выдаёт per-request nonce, строгий `script-src
  'self' 'nonce' 'strict-dynamic'` — барьер против внедрения дрейнер-скрипта через XSS.
  Проверено на прод-сборке: сайт гидрируется, 0 нарушений. Лендинг переведён в
  `force-dynamic` (иначе статический HTML не может получить per-request nonce).
  В dev CSP ослаблен (Turbopack HMR требует eval/inline).
- **SEO:** `app/robots.ts`, `app/sitemap.ts`, OG-картинка, брендовый фавикон, мета.
- **Устойчивость:** `app/error.tsx`, `app/global-error.tsx` (границы ошибок),
  `app/not-found.tsx`, баннеры сетевых ошибок в игре и борде.
- **Мониторинг:** `GET /api/health` — проверка стора + флаги конфигурации.

## M2 — кошелёк и буст (реализовано)
- wagmi + viem (connectkit несовместим с React 19 → своя кнопка коннекта в теме).
- Коннектор: injected (MetaMask/in-app). WalletConnect/Coinbase добавим при projectId.
- Вход: SIWE-стиль. `GET /api/auth/nonce` → подпись сообщения кошельком →
  `POST /api/auth/verify` (viem verifyMessage) → идентичность = `wallet:<addr>` (один кошелёк = один аккаунт).
- Буст ×1.5: сервер читает баланс $VLTR on-chain (`lib/vltr.ts`) и сам ставит `boost`.
  Клиент буст НЕ задаёт (иначе накрутил бы холд). `DEV_FORCE_BOOST=1` — тест пути буста.
- Проверено: SIWE end-to-end (valid→200 wallet-identity, битая подпись→401), буст→mult 1.5.

### Безопасность входа кошельком (усилено 2026-07-24)
- Вход переведён на полноценный **SIWE / EIP-4361** через `viem/siwe` (аудированные примитивы).
- Сервер (`/api/auth/verify`) проверяет: **домен** (анти-фишинг/replay на чужом сайте),
  **nonce** (одноразовый, из httpOnly-cookie), **срок действия** (5 мин), **подпись**.
  `AUTH_DOMAIN` в проде пинит домен (Host можно подделать).
- Rate-limit на `/api/auth/*` и `/api/crank` (`lib/ratelimit.ts`, скользящее окно по IP).
- `node scripts/test-auth.mjs` (`npm run test:auth`) — 7 проверок: валидный вход +
  отказы для чужого домена, чужого nonce, протухшей/битой/чужой подписи.
- **Модель угроз:** мы НЕ шлём транзакций и НЕ просим approve — только читаем подпись
  сообщения и публичный баланс. Через флоу нечего задрейнить. Приватники не трогаем.
- TODO (бэклог): ERC-1271 (смарт-кошельки) — нужен рабочий RPC; строгий CSP c nonce.

## Скины сейфа по рангу (реализовано)
- 6 скинов: база → топ-1000 → топ-500 → топ-100 → топ-10 → #1. Растёт не только палитра,
  но и детали: камни, золотой карниз, зубцы, корона. Логика — `lib/skins.ts` (покрыта тестами).
- **Гейтинг по размеру комьюнити:** скин «TOP N» включается только когда игроков БОЛЬШЕ N.
  Иначе в топ-N попадают все и награда обесценивается. При 100 участниках работают только
  топ-10 и топ-1; при 501 открывается топ-500 и т.д. Потолок едет вверх вместе с комьюнити,
  поэтому прокачиваться всегда есть куда (решение Егора, 2026-07-24).
- Закрытые скины на витрине показываются тёмным силуэтом + «needs N+ stackers» — видно цель.
- Ранг и число игроков берутся из серверного `/api/leaderboard` и поднимаются через
  `GameSection` в игру: без лишнего пересчёта на каждый опрос состояния.

## Боты для тестов борда
`node scripts/seed-bots.mjs 239` — набивает борд ботами (степенное распределение стека),
`--clear` убирает. Нужно, чтобы потрогать гейтинг скинов: топ-100 включается только при
>100 игроков, без массовки это не проверить. После сидинга нужен рестарт dev-сервера —
файловый стор кэширует данные в памяти.

**Честность:** боты пишутся с префиксом `bot:` и помечаются на борде тегом `test`.
Борд когда-нибудь будет делить реальные токены, поэтому неотличимые фейки на нём
недопустимы. Скрипт отказывается работать при заданном `DATABASE_URL` (прод).
Перед реальным запуском — прогнать `--clear`.
