# VAULTLER — карта проекта

Мем-токен **$VLTR** + ежедневный минигейм на Robinhood Chain (Arbitrum Orbit L2).
Игрок жмёт CRANK — машина заводится на 24ч и стакает игровой `$STACK`, пока он спит.
Вернулся в 12-часовое окно — стрик и множитель растут (компаунд). Проспал — приходит
рейдер и скимит часть стека. Топ-10 недельного борда делит пул из торговых фисов.
Вайб: анти-трейдинг, про-стакинг. Визуал — пиксель-вестерн.

Сайт — это лендинг + игра + борд на одной странице. Кастодии средств нет: кошелёк нужен
только для подписи входа и чтения баланса.

## Главный инвариант: сервер — источник правды

Стек, стрик, тайминги, буст и ранг считаются и хранятся **на сервере**. Клиент только
рисует. Причина: борд делит реальные токены — в прототипе состояние жило в
`window.storage`, и любой мог выставить себе `999999` через DevTools.

Нельзя ломать никогда:
1. API не принимает от клиента ни время, ни стек, ни стрик, ни флаг буста.
2. Любая мутация стейта идёт через `store.mutate` (лок / транзакция) — иначе гонка
   двух одновременных кранков даёт двойное начисление.
3. `settle()` идемпотентен по `lastSettleAt` — частый поллинг не должен раздувать стек.
4. Тир холдерского буста ставит только сервер, прочитав баланс и эмиссию on-chain, и
   перепроверяет его **на кранке** — иначе холдер продаёт токен и сохраняет множитель
   навсегда. «Не смог прочитать» — это не «баланс нулевой»: при отказе RPC прежний тир
   сохраняется. Множитель зависит от **доли в эмиссии** (лестница `HOLDER_TIERS`,
   верх ×5), а не от абсолютного числа токенов и не от места среди игроков: перцентиль
   накручивался бы бесплатными сессиями.
5. Наружу не отдаются internal id (`dev:uuid`, `wallet:0x…`) и адрес игрока,
   скрывшего кошелёк.
6. Идентичность берётся только из **подписанного** значения (cookie или заголовок от
   proxy) и проверяется в самом роуте. Заголовку `x-vaultler-id` на слово не верим:
   иначе один `curl` отдаёт любой аккаунт, если proxy почему-либо не отработал.
7. Каждый ответ API — `no-store` (`jsonNoStore`). Персональные данные и `Set-Cookie`
   в общем кэше = выдача чужой сессии другому пользователю.
8. Каждый POST проверяет происхождение (`sameOriginOk`) — `SameSite` не единственный
   барьер против CSRF.
6. Тексты на сайте — часть безопасности: не обещаем APY, не намекаем на депозиты/кастодию,
   пул называем призом за место в игре, а не дивидендом на холд.

## Стек и команды

Next.js **16** (App Router) · React 19 · TypeScript · plain CSS · Prisma/Postgres ·
wagmi + viem · vitest. Деплой — Vercel.

```bash
npm run dev                  # http://localhost:3000
GAME_MODE=demo npm run dev   # быстрый цикл петли: 30с завод / 15с окно вместо 24ч/12ч
npm test                     # юнит-тесты чистой логики
npm run test:auth            # e2e SIWE + регрессии аудита против запущенного dev-сервера
npm run test:profile         # e2e ников и приватности
npm run test:boost           # e2e буста ×5 против локального чейна (anvil, см. docs/testing.md)
npm run check:secrets        # аудит секретов (дерево + вся история git)
```

Без `DATABASE_URL` используется файловый стор `.data/players.json` — БД для разработки
не нужна.

## Правила работы в этом репозитории

- Next.js здесь **версии 16** — см. предупреждение выше: перед правкой фреймворочных
  вещей читать `node_modules/next/dist/docs/`. Middleware заменён на `proxy.ts`.
- Все API-роуты: `runtime = "nodejs"`, `dynamic = "force-dynamic"`. Лендинг тоже
  `force-dynamic` — статический HTML не получит per-request CSP-nonce.
- Импорты через `@/`. Комментарии в коде — на русском, объясняют **почему**, не «что».
- Логику держим в чистых модулях `lib/*` и покрываем тестами; роуты остаются тонкими.
- Умышленно небезопасный код (для обучения) помечать `// УЯЗВИМО:`.
- Секреты — только в `.env.local` и env Vercel. В `.env.example` только пустые плейсхолдеры.
- Репозиторий приватный. Перед пушем обязателен `npm run check:secrets`
  (подключается хуком: `git config core.hooksPath .githooks`).
- Не автоматизировать выплаты пула и не создавать аккаунты/организации — это решения
  и действия владельца проекта.

## Статус

- **M1–M3, M5 готовы:** ядро петли, сторы, сессия, API, вход кошельком (SIWE), серверный
  буст, недельный борд + общий сейф, лендинг и бренд, скины сейфа по рангу.
- **M4 в работе:** полировка, анти-чит, подготовка к деплою. Сделаны: rate-limit через
  общий стор (Vercel KV / Upstash, фолбэк в память), журнал кранков `CrankLog`,
  файловый стор больше не попадает в прод-бандл, петля больше не обрывается в dev
  (файловый стор сверяет отпечаток файла), холдерский буст переведён на лестницу тиров
  по доле в эмиссии.
- **Главное незакрытое:** подключить KV и выставить `KV_REST_API_*` (иначе лимиты
  считаются по инстансам и обходятся), убрать тестовых ботов, реальный конфиг сети/токена,
  калибровка баланса, политика выплат. Детали — `docs/deployment.md` и `NOTES.md`.
- **Спринт 1.1 (Telegram-бот напоминаний) готов в коде:** привязка одноразовым кодом,
  вебхук с двойным секретом (путь + заголовок), рассылка «окно открылось»/«2 часа до
  рейдера» через GitHub Actions (не Vercel Cron — план Hobby), бот не мутирует стейт.
  Осталось на владельце: создать бота, задать env, `prisma db push`, `setWebhook`
  (`docs/deployment.md` → «Telegram-бот напоминаний»).
